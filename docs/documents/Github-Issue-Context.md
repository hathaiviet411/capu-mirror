## 📝 Issue作成パターン

### 標準テンプレート構造

```markdown
## 📝 Issue概要
**タスクID**: [ID]
**エピック**: [エピック名]
**機能**: [機能説明]

## 🎯 目的・背景
### なぜこの機能が必要か
### 期待される効果

## 📋 受け入れ条件（Acceptance Criteria）
### 機能要件
### セキュリティ要件（必要に応じて）
### パフォーマンス要件（必要に応じて）

## 🛠️ 実装タスク
### [カテゴリ別のタスク一覧]

## 🔗 依存関係
### 前提条件
### 後続タスク

## 💡 技術詳細
### 使用技術・サービス
### 実装アプローチ
### 注意点・課題

## 📊 パフォーマンス目標（必要に応じて）

## 📋 チェックリスト
### [実装前後のチェック項目]

## 📊 見積もり・優先度
- **工数**: [日数]
- **複雑度**: 🟢低/🟡中/🔴高
- **優先度**: 🔥高/🟡中/🟢低

## 🏷️ ラベル
`[関連ラベル]`

## 👥 アサイニー
- @[担当者]

## 📎 関連リンク
- [関連ドキュメント・Issue]

🤖 Generated with [Claude Code](https://claude.ai/code)
Co-Authored-By: Claude <noreply@anthropic.com>
```

### 命名規則
- **Issue タイトル**: `[タスクID] タスク名`
- **タスクID形式**: `[カテゴリ]-[番号]` (例: AUTH-01, API-01, DB-01)
- **エピック**: 機能別グループ (認証システム、API開発、データベース設計等)

### セクション記述ガイドライン

#### 目的・背景
- **なぜ必要か**: ビジネス要件・技術的必要性
- **期待される効果**: 実装後の改善点・メリット

#### 受け入れ条件
- **機能要件**: 必須実装項目
- **セキュリティ要件**: セキュリティ関連の必須項目
- **パフォーマンス要件**: 性能・速度に関する要件

#### 実装タスク
- カテゴリ別に整理 (設定・構築、テスト・検証、ドキュメント等)
- チェックボックス形式で進捗管理可能

#### 技術詳細
- **使用技術**: 関連技術・サービス・ライブラリ
- **実装アプローチ**: コード例・設定例
- **注意点・課題**: 実装時の留意点

## 🔧 実行コマンド例

### 基本的なIssue作成コマンド
```bash
gh issue create --title "[タスクID] タスク名" --body "$(cat <<'EOF'
[Issue内容]
EOF
)"
```

### ラベル付きIssue作成
```bash
gh issue create --title "[タスクID] タスク名" --body "$(cat <<'EOF'
[Issue内容]
EOF
)" --label "priority:high" --label "type:feature"
```

### 実際の実行例
```bash
gh issue create --title "[ENV-01] 環境変数一覧設計・定義" --body "$(cat <<'EOF'
## 📝 Issue概要
**タスクID**: ENV-01
**エピック**: 環境変数管理  
**機能**: 開発/ステージング/本番環境の環境変数一覧設計・定義
...
EOF
)"
```
