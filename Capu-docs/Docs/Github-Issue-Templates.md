## 📝 使用ガイドライン

### テンプレート選択指針

1. **基盤開発用**: 認証、API、データベース等のバックエンド開発
2. **UI/UX開発用**: 画面・インタラクション等のフロントエンド開発  
3. **インフラ用**: デプロイ、監視、CI/CD等のインフラストラクチャ
4. **テスト用**: 各種テストの実装・実行
5. **バグ修正用**: 不具合の修正・対応

### 共通ルール

- **タイトル**: `[タスクID] 機能名` の形式で記載
- **ラベル**: 適切なラベルを必ず設定
- **アサイニー**: 担当者を必ず設定
- **マイルストーン**: 対応するマイルストーンに設定
- **受け入れ条件**: 完了の定義を明確に記載
- **依存関係**: 前提条件・後続タスクを必ず記載

### ベストプラクティス

1. **SMART原則**: Specific, Measurable, Achievable, Relevant, Time-bound
2. **DoD (Definition of Done)**: 完了の定義を明確にする
3. **適切な粒度**: 1Issue = 1-3日の作業量を目安
4. **トレーサビリティ**: 要件からテストまで追跡可能にする
5. **継続的改善**: テンプレートは定期的に見直し・改善する
