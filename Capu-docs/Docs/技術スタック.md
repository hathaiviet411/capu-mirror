# Capu システム 技術スタック

## 概要
このドキュメントは、Capuシステムで採用している技術スタック及びアーキテクチャについて記載しています。

## 技術スタック一覧

### 開発テンプレート
| 技術 | 用途 | 説明 |
|------|------|------|
| **T3 Stack** | 開発テンプレート | TypeScript、Next.js、tRPC、Prisma、NextAuth.jsを統合したフルスタック開発テンプレート |

### フロントエンド
| 技術 | 用途 | 説明 |
|------|------|------|
| **Next.js** | フロントエンドフレームワーク | Reactベースのフルスタックフレームワーク |
| **TypeScript** | 型安全性 | 静的型付けによる開発効率とコード品質の向上 |
| **Tailwind CSS** | スタイリング | ユーティリティファーストのCSSフレームワーク |
| **tRPC** | API通信 | エンドツーエンド型安全なAPI通信 |
| **Vercel** | ホスティングプラットフォーム | フロントエンドアプリケーションのデプロイ・配信 |
| **Vercel CDN** | コンテンツ配信 | 静的コンテンツの高速配信 |

### バックエンド・API
| 技術 | 用途 | 説明 |
|------|------|------|
| **Google Cloud Run** | サーバーレスコンテナ | APIサーバーのホスティング |
| **Cloud Run Auth API** | 認証API | JWT管理とセキュリティ処理 |
| **tRPC** | API層 | 型安全なAPI開発とクライアント-サーバー間通信 |

### データベース・ORM
| 技術 | 用途 | 説明 |
|------|------|------|
| **Supabase** | メインデータベース | PostgreSQLベースのBaaS |
| **Prisma** | ORM | 型安全なデータベースアクセス層 |

#### データベーステーブル構成
- `users` - ユーザー情報管理
- `casts` - キャスト情報管理
- `cast_applications` - キャスト申請情報管理

### ファイルストレージ
| 技術 | 用途 | 説明 |
|------|------|------|
| **Cloudflare R2** | オブジェクトストレージ | 画像、動画、ドキュメントなどのファイル管理 |

### 認証・セキュリティ
| 技術 | 用途 | 説明 |
|------|------|------|
| **NextAuth.js** | 認証ライブラリ | Next.js用の包括的な認証ソリューション |
| **LINE OAuth** | ユーザー認証 | 認証の基盤システム |
| **JWT (JSON Web Token)** | 認証トークン | セッション管理 |
| **localStorage** | クライアントストレージ | セッション情報の保存 |
| **HTTPS** | 通信暗号化 | 全ての通信で使用 |
| **OAuth 2.0** | 認証プロトコル | LINE認証フロー |

### 決済システム

|------|------|------|
| **Stripe** | 決済処理 | クレジットカード決済、サブスクリプション管理 |

### 外部サービス連携
| サービス | 用途 | 説明 |
|----------|------|------|
| **LINE API** | 外部連携 | 認証、プロフィール取得、通知送信 |
| **Stripe API** | 決済連携 | 決済処理、請求管理、顧客管理 |
| **Cloudflare R2 API** | ファイル管理 | ファイルアップロード、ダウンロード、管理 |

## アーキテクチャの特徴

### 1. T3 Stack による統合開発環境
- **Type-Safe Full Stack**: TypeScript + tRPC による完全型安全
- **Modern Stack**: 最新のベストプラクティスを組み合わせ
- **開発者体験**: 優れたDXと生産性の向上
- **コード品質**: 型安全性による堅牢なアプリケーション

### 2. サーバーレスアーキテクチャ
- **Vercel** + **Google Cloud Run** の組み合わせ
- スケーラビリティの確保
- 運用コストの最適化
- 自動スケーリング

### 3. JAMstack アプローチ
- JavaScript、APIs、Markupの組み合わせ
- 高いパフォーマンス
- CDNによる高速配信
- セキュリティの向上

### 4. マイクロサービス指向
- フロントエンドとバックエンドの分離
- 独立したデプロイメント
- 技術スタックの柔軟性

### 5. 統合ファイル管理
- **Cloudflare R2**による高速ファイル配信
- グローバルCDNとの統合
- コスト効率的なストレージ

## 開発・運用の利点

### パフォーマンス
- **Vercel CDN**による高速コンテンツ配信
- **Cloudflare R2**による世界規模のファイル配信
- **Cloud Run**のコンテナベース高速起動
- **Next.js**のSSR/SSG最適化

- **LINE OAuth**による安全な認証
- **JWT**によるステートレス認証
- **HTTPS**による通信暗号化
- **Stripe**による安全な決済処理

### 開発効率
- **T3 Stack**によるフルスタック開発環境
- **TypeScript**による型安全性
- **Prisma**による型安全なデータベースアクセス
- **tRPC**による型安全なAPI開発

### 運用・保守性
- **サーバーレス**による運用負荷軽減
- **マネージドサービス**による可用性確保
- **Cloud Run**の自動スケーリング
- **Cloudflare R2**の高可用性ストレージ

## 注意事項・制約

1. **ベンダーロックイン**: Vercel、Supabase、Cloudflare、Stripeへの依存
2. **冷却時間**: Cloud Runのコールドスタート
3. **データ移行**: Supabaseからの移行コスト
4. **API制限**: LINE API、Stripe APIの利用制限
5. **学習コスト**: T3 Stackの技術習得コスト
6. **ストレージコスト**: Cloudflare R2の利用料金

## 今後の技術選定指針

- **型安全性**: TypeScriptとtRPCによる完全型安全な開発
- **コスト効率性**: 運用コストの最適化を重視
- **開発速度**: 迅速な機能開発を可能にする技術選択
- **スケーラビリティ**: ユーザー増加に対応できるアーキテクチャ
- **保守性**: 長期的な保守・運用のしやすさ
- **ユーザー体験**: 高性能で安全なアプリケーション提供
