# Capu 業務フローシーケンス図

## 概要
このドキュメントは、Capuシステムにおける主要な業務フローを詳細なシーケンス図で示したものです。システム構成図.mdで定義されたアーキテクチャを基に、実際のユーザー操作から各システムコンポーネントの連携までを時系列で記載しています。

## 1. メッセージング業務フロー

```mermaid
sequenceDiagram
    participant ゲスト
    participant Next.js(フロントエンド)
    participant tRPC(API層)
    participant WebSocket(リアルタイム通信)
    participant Supabase(データベース)
    participant CloudflareR2(ファイルストレージ)

    Note over ゲスト, CloudflareR2: リアルタイムメッセージング

    ゲスト->>Next.js(フロントエンド): メッセージ画面にアクセス
    Next.js(フロントエンド)->>tRPC(API層): JWT認証確認
    tRPC(API層)->>Supabase(データベース): セッション検証
    Supabase(データベース)->>tRPC(API層): 認証成功
    tRPC(API層)->>Next.js(フロントエンド): 認証済み状態を返却
    
    Next.js(フロントエンド)->>WebSocket(リアルタイム通信): WebSocket接続確立
    WebSocket(リアルタイム通信)->>Next.js(フロントエンド): 接続確立完了
    
    Next.js(フロントエンド)->>tRPC(API層): メッセージ履歴取得API
    tRPC(API層)->>Supabase(データベース): messagesテーブルからSELECT
    Supabase(データベース)->>tRPC(API層): メッセージ履歴を返却
    tRPC(API層)->>Next.js(フロントエンド): メッセージ履歴レスポンス
    Next.js(フロントエンド)->>ゲスト: メッセージ一覧を表示

    Note over ゲスト, CloudflareR2: 画像付きメッセージ送信

    ゲスト->>Next.js(フロントエンド): 画像選択ボタンをクリック
    Next.js(フロントエンド)->>ゲスト: ファイル選択ダイアログを表示
    ゲスト->>Next.js(フロントエンド): 画像ファイルを選択
    Next.js(フロントエンド)->>tRPC(API層): 画像アップロードAPI呼び出し
    tRPC(API層)->>CloudflareR2(ファイルストレージ): 画像ファイルをアップロード
    CloudflareR2(ファイルストレージ)->>tRPC(API層): アップロード完了とURL返却
    tRPC(API層)->>Supabase(データベース): 画像URLを含むメッセージをINSERT
    Supabase(データベース)->>tRPC(API層): 保存完了
    tRPC(API層)->>WebSocket(リアルタイム通信): リアルタイムメッセージ配信
    WebSocket(リアルタイム通信)->>Next.js(フロントエンド): 画像メッセージを受信
    Next.js(フロントエンド)->>ゲスト: 画像付きメッセージを表示

    Note over ゲスト, CloudflareR2: テキストメッセージ送信

    ゲスト->>Next.js(フロントエンド): メッセージを入力・送信
    Next.js(フロントエンド)->>tRPC(API層): メッセージ送信API呼び出し
    tRPC(API層)->>Supabase(データベース): messagesテーブルにINSERT
    Supabase(データベース)->>tRPC(API層): 保存完了
    tRPC(API層)->>WebSocket(リアルタイム通信): リアルタイムメッセージ配信
    WebSocket(リアルタイム通信)->>Next.js(フロントエンド): メッセージを受信側に配信
    Next.js(フロントエンド)->>ゲスト: メッセージ送信完了とリアルタイム表示

    Note over ゲスト, CloudflareR2: 既読状態管理

    Next.js(フロントエンド)->>WebSocket(リアルタイム通信): 既読状態を送信
    WebSocket(リアルタイム通信)->>tRPC(API層): 既読状態更新
    tRPC(API層)->>Supabase(データベース): messagesテーブルの既読フラグをUPDATE
    Supabase(データベース)->>tRPC(API層): 更新完了
    tRPC(API層)->>WebSocket(リアルタイム通信): 既読状態を送信者に通知
    WebSocket(リアルタイム通信)->>Next.js(フロントエンド): 既読表示を更新
```

## 2. 決済・ポイント業務フロー

```mermaid
sequenceDiagram
    participant ゲスト
    participant Next.js(フロントエンド)
    participant tRPC(API層)
    participant Stripe(決済API)
    participant Supabase(データベース)

    Note over ゲスト, Supabase: クレジットカード登録

    ゲスト->>Next.js(フロントエンド): 支払い情報画面にアクセス
    Next.js(フロントエンド)->>tRPC(API層): 決済手段取得API
    tRPC(API層)->>Supabase(データベース): payment_methodsテーブルからSELECT
    Supabase(データベース)->>tRPC(API層): 登録済み決済手段を返却
    tRPC(API層)->>Next.js(フロントエンド): マスク処理済みカード情報
    Next.js(フロントエンド)->>ゲスト: 決済手段一覧を表示

    ゲスト->>Next.js(フロントエンド): 「お支払い情報を追加する」をクリック
    Next.js(フロントエンド)->>ゲスト: カード登録フォームを表示
    ゲスト->>Next.js(フロントエンド): カード情報を入力・送信
    Next.js(フロントエンド)->>Stripe(決済API): カード情報検証・トークン化
    Stripe(決済API)->>Next.js(フロントエンド): セキュアトークンを返却
    Next.js(フロントエンド)->>tRPC(API層): トークンでカード登録API
    tRPC(API層)->>Stripe(決済API): 顧客・決済手段を作成
    Stripe(決済API)->>tRPC(API層): 決済手段IDを返却
    tRPC(API層)->>Supabase(データベース): payment_methodsテーブルにINSERT
    Supabase(データベース)->>tRPC(API層): 保存完了
    tRPC(API層)->>Next.js(フロントエンド): 登録完了通知
    Next.js(フロントエンド)->>ゲスト: カード登録完了・一覧更新

    Note over ゲスト, Supabase: 決済処理

    ゲスト->>Next.js(フロントエンド): キャスト予約・決済を実行
    Next.js(フロントエンド)->>tRPC(API層): 決済処理API呼び出し
    tRPC(API層)->>Supabase(データベース): 決済対象の予約情報を取得
    Supabase(データベース)->>tRPC(API層): 予約詳細・料金情報を返却
    tRPC(API層)->>Stripe(決済API): 決済意図(PaymentIntent)を作成
    Stripe(決済API)->>tRPC(API層): 決済意図IDを返却
    tRPC(API層)->>Stripe(決済API): 決済を実行
    
    alt 決済成功
        Stripe(決済API)->>tRPC(API層): 決済成功通知
        tRPC(API層)->>Supabase(データベース): payment_historyテーブルにINSERT
        Supabase(データベース)->>tRPC(API層): 決済履歴保存完了
        tRPC(API層)->>Supabase(データベース): 予約ステータスを「確定」に更新
        Supabase(データベース)->>tRPC(API層): 予約確定完了
        tRPC(API層)->>Next.js(フロントエンド): 決済成功レスポンス
        Next.js(フロントエンド)->>ゲスト: 決済完了・予約確定通知
    else 決済失敗
        Stripe(決済API)->>tRPC(API層): 決済エラー通知
        tRPC(API層)->>Supabase(データベース): エラーログを記録
        tRPC(API層)->>Next.js(フロントエンド): 決済エラーレスポンス
        Next.js(フロントエンド)->>ゲスト: 決済失敗・代替カード案内
    end

    Note over ゲスト, Supabase: ポイント履歴確認

    ゲスト->>Next.js(フロントエンド): ポイント履歴画面にアクセス
    Next.js(フロントエンド)->>tRPC(API層): ポイント履歴取得API
    tRPC(API層)->>Supabase(データベース): point_historyテーブルからSELECT
    Supabase(データベース)->>tRPC(API層): ポイント取引履歴を返却
    tRPC(API層)->>Next.js(フロントエンド): ポイント履歴レスポンス
    Next.js(フロントエンド)->>ゲスト: ポイント履歴一覧を表示
```

## 3. キャスト検索・予約業務フロー

```mermaid
sequenceDiagram
    participant ゲスト
    participant Next.js(フロントエンド)
    participant tRPC(API層)
    participant Supabase(データベース)
    participant CloudflareR2(ファイルストレージ)

    Note over ゲスト, CloudflareR2: キャスト検索

    ゲスト->>Next.js(フロントエンド): ホーム画面で検索ボタンをクリック
    Next.js(フロントエンド)->>ゲスト: 検索モーダルを表示
    ゲスト->>Next.js(フロントエンド): 検索条件を入力(エリア、年齢、ジャンル等)
    Next.js(フロントエンド)->>tRPC(API層): キャスト検索API呼び出し
    tRPC(API層)->>Supabase(データベース): castsテーブルから条件検索
    Supabase(データベース)->>tRPC(API層): 検索結果のキャスト一覧
    tRPC(API層)->>CloudflareR2(ファイルストレージ): キャストプロフィール画像URL取得
    CloudflareR2(ファイルストレージ)->>tRPC(API層): 画像URLを返却
    tRPC(API層)->>Next.js(フロントエンド): 検索結果レスポンス
    Next.js(フロントエンド)->>ゲスト: キャスト一覧を表示

    Note over ゲスト, CloudflareR2: キャスト詳細確認

    ゲスト->>Next.js(フロントエンド): キャストプロフィールをクリック
    Next.js(フロントエンド)->>tRPC(API層): キャスト詳細取得API
    tRPC(API層)->>Supabase(データベース): castプロフィール詳細をSELECT
    Supabase(データベース)->>tRPC(API層): キャスト詳細情報を返却
    tRPC(API層)->>CloudflareR2(ファイルストレージ): 追加画像・動画取得
    CloudflareR2(ファイルストレージ)->>tRPC(API層): メディアファイルURLを返却
    tRPC(API層)->>Next.js(フロントエンド): キャスト詳細レスポンス
    Next.js(フロントエンド)->>ゲスト: キャスト詳細モーダルを表示

    Note over ゲスト, CloudflareR2: 予約・メッセージ開始

    ゲスト->>Next.js(フロントエンド): 「メッセージを送る」ボタンをクリック
    Next.js(フロントエンド)->>tRPC(API層): 本人確認状態チェックAPI
    tRPC(API層)->>Supabase(データベース): ユーザーの本人確認ステータス確認
    
    alt 本人確認未完了
        Supabase(データベース)->>tRPC(API層): 本人確認未完了ステータス
        tRPC(API層)->>Next.js(フロントエンド): 本人確認必須レスポンス
        Next.js(フロントエンド)->>ゲスト: 本人確認画面に誘導
    else 本人確認完了
        Supabase(データベース)->>tRPC(API層): 本人確認完了ステータス
        tRPC(API層)->>Supabase(データベース): チャットルーム作成・JOIN
        Supabase(データベース)->>tRPC(API層): チャットルーム作成完了
        tRPC(API層)->>Next.js(フロントエンド): チャット開始レスポンス
        Next.js(フロントエンド)->>ゲスト: メッセージ画面に遷移
    end

    Note over ゲスト, CloudflareR2: 日程調整・予約確定

    ゲスト->>Next.js(フロントエンド): 日程提案ボタンをクリック
    Next.js(フロントエンド)->>ゲスト: 日程選択モーダルを表示
    ゲスト->>Next.js(フロントエンド): 希望日時・時間・場所を選択
    Next.js(フロントエンド)->>tRPC(API層): 料金自動計算API
    tRPC(API層)->>Supabase(データベース): キャスト料金設定を取得
    Supabase(データベース)->>tRPC(API層): 時間単価・基本料金を返却
    tRPC(API層)->>Next.js(フロントエンド): 計算済み料金レスポンス
    Next.js(フロントエンド)->>ゲスト: 料金表示・確認画面
    ゲスト->>Next.js(フロントエンド): 日程提案を送信
    Next.js(フロントエンド)->>tRPC(API層): 予約申請作成API
    tRPC(API層)->>Supabase(データベース): bookingsテーブルにINSERT
    Supabase(データベース)->>tRPC(API層): 予約申請保存完了
    tRPC(API層)->>Next.js(フロントエンド): 日程提案送信完了
    Next.js(フロントエンド)->>ゲスト: 日程提案メッセージを表示
```

## 4. 本人確認業務フロー

```mermaid
sequenceDiagram
    participant ゲスト
    participant Next.js(フロントエンド)
    participant tRPC(API層)
    participant Supabase(データベース)

    ゲスト->>Next.js(フロントエンド): 身分証明書の種類を選択
    Next.js(フロントエンド)->>ゲスト: 書類アップロード画面を表示

    Next.js(フロントエンド)->>tRPC(API層): 画像アップロードAPI呼び出し
    tRPC(API層)->>CloudflareR2(ファイルストレージ): 身分証画像をアップロード
    CloudflareR2(ファイルストレージ)->>tRPC(API層): アップロード完了・URLを返却
    
    ゲスト->>Next.js(フロントエンド): 身分証明書画像を選択(裏面)
    Next.js(フロントエンド)->>tRPC(API層): 画像アップロードAPI呼び出し
    tRPC(API層)->>CloudflareR2(ファイルストレージ): 身分証画像をアップロード

    ゲスト->>Next.js(フロントエンド): 個人情報を入力(氏名、生年月日等)

    tRPC(API層)->>Supabase(データベース): 審査結果をUPDATE(承認/却下)

    alt 審査承認
        ゲスト->>Next.js(フロントエンド): アプリに再アクセス
        Next.js(フロントエンド)->>tRPC(API層): 本人確認状態取得API
        tRPC(API層)->>Supabase(データベース): user_verificationsテーブルからSELECT

    else 審査却下
        ゲスト->>Next.js(フロントエンド): アプリに再アクセス
        Next.js(フロントエンド)->>tRPC(API層): 本人確認状態取得API
```

## 5. ファイルアップロード業務フロー

```mermaid
sequenceDiagram
    participant ユーザー
    participant Next.js(フロントエンド)
    participant tRPC(API層)
    participant CloudflareR2(ファイルストレージ)
    participant Supabase(データベース)

    Note over ユーザー, Supabase: プロフィール画像アップロード

    ユーザー->>Next.js(フロントエンド): プロフィール編集画面にアクセス
    Next.js(フロントエンド)->>ユーザー: 画像アップロード画面を表示
    ユーザー->>Next.js(フロントエンド): 画像ファイルを選択
    Next.js(フロントエンド)->>Next.js(フロントエンド): 画像形式・サイズ検証
    
    alt 画像検証成功
        Next.js(フロントエンド)->>tRPC(API層): 画像アップロード前処理API
        tRPC(API層)->>CloudflareR2(ファイルストレージ): アップロード用署名URL取得
        CloudflareR2(ファイルストレージ)->>tRPC(API層): 署名URL・一意ファイル名を返却
        tRPC(API層)->>Next.js(フロントエンド): アップロード情報レスポンス
        
        Next.js(フロントエンド)->>CloudflareR2(ファイルストレージ): 署名URLで直接アップロード
        CloudflareR2(ファイルストレージ)->>Next.js(フロントエンド): アップロード完了通知
        
        Next.js(フロントエンド)->>tRPC(API層): アップロード完了後処理API
        tRPC(API層)->>CloudflareR2(ファイルストレージ): ファイル存在確認
        CloudflareR2(ファイルストレージ)->>tRPC(API層): ファイル確認完了・公開URL
        tRPC(API層)->>Supabase(データベース): ユーザープロフィール画像URLを更新
        Supabase(データベース)->>tRPC(API層): プロフィール更新完了
        tRPC(API層)->>Next.js(フロントエンド): 画像更新完了レスポンス
        Next.js(フロントエンド)->>ユーザー: 新しいプロフィール画像を表示
    else 画像検証失敗
        Next.js(フロントエンド)->>ユーザー: エラーメッセージ表示(形式・サイズエラー)
    end

    Note over ユーザー, Supabase: 複数画像一括アップロード

    ユーザー->>Next.js(フロントエンド): 複数画像選択(キャストギャラリー)
    Next.js(フロントエンド)->>Next.js(フロントエンド): 全画像の一括検証
    
    loop 各画像ファイル
        Next.js(フロントエンド)->>tRPC(API層): 個別画像アップロード前処理
        tRPC(API層)->>CloudflareR2(ファイルストレージ): 署名URL取得
        CloudflareR2(ファイルストレージ)->>tRPC(API層): 署名URL返却
        tRPC(API層)->>Next.js(フロントエンド): アップロード情報
        Next.js(フロントエンド)->>CloudflareR2(ファイルストレージ): 並列アップロード実行
        CloudflareR2(ファイルストレージ)->>Next.js(フロントエンド): 個別アップロード完了
    end
    
    Next.js(フロントエンド)->>tRPC(API層): 一括アップロード完了処理API
    tRPC(API層)->>Supabase(データベース): ギャラリー画像URL一括INSERT
    Supabase(データベース)->>tRPC(API層): 一括保存完了
    tRPC(API層)->>Next.js(フロントエンド): 全画像登録完了レスポンス
    Next.js(フロントエンド)->>ユーザー: ギャラリー更新・プレビュー表示

    Note over ユーザー, Supabase: ファイル削除

    ユーザー->>Next.js(フロントエンド): 画像削除ボタンをクリック
    Next.js(フロントエンド)->>tRPC(API層): ファイル削除API呼び出し
    tRPC(API層)->>Supabase(データベース): 削除対象ファイル情報を取得
    Supabase(データベース)->>tRPC(API層): ファイルURL・メタデータを返却
    tRPC(API層)->>CloudflareR2(ファイルストレージ): ファイル削除実行
    CloudflareR2(ファイルストレージ)->>tRPC(API層): 削除完了確認
    tRPC(API層)->>Supabase(データベース): データベースからファイル情報を削除
    Supabase(データベース)->>tRPC(API層): データ削除完了
    tRPC(API層)->>Next.js(フロントエンド): ファイル削除完了レスポンス
    Next.js(フロントエンド)->>ユーザー: 画像削除完了・表示更新
```

## 業務フローの技術的特徴

### 1. 型安全性の確保
- **tRPC**: フロントエンドからバックエンドまで完全型安全
- **Prisma ORM**: データベースアクセスの型安全性
- **TypeScript**: 全層での静的型チェック

### 2. リアルタイム通信
- **WebSocket**: メッセージング、通知のリアルタイム配信
- **Server-Sent Events**: ライブ更新の効率的な実装
- **楽観的UI更新**: ユーザビリティ向上

### 3. セキュリティ対策
- **JWT認証**: ステートレスな認証管理
- **OAuth 2.0**: LINE認証による信頼性確保
- **署名URL**: ファイルアップロードのセキュリティ
- **入力検証**: 全API層でのバリデーション

### 4. パフォーマンス最適化
- **CDN活用**: Vercel、Cloudflare R2での高速配信
- **並列処理**: 複数ファイルの同時アップロード
- **キャッシュ戦略**: 頻繁にアクセスされるデータの最適化
- **遅延読み込み**: 必要な時点でのリソース取得

### 5. 可用性・拡張性
- **サーバーレス**: 自動スケーリングによる可用性確保
- **マイクロサービス**: 独立したコンポーネント設計
- **エラーハンドリング**: 段階的な機能縮退
- **フォールバック機能**: 障害時の代替処理

## 注意事項

1. **認証管理**: 全業務フローでJWT認証が前提
2. **ファイルサイズ制限**: アップロード時の適切な制限設定
3. **レート制限**: API呼び出し頻度の制御
4. **監視・ログ**: 各業務フローでの適切なログ収集
5. **GDPR対応**: 個人データの適切な管理・削除
